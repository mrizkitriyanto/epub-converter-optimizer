# M3: XTC/XTCH Output + Page Style Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce XTC (1-bit) and XTCH (4-level gray) files that open on every Xteink firmware. Add an xtctool-level "page style" (font, size, weight, line height, margins, alignment, hyphenation, dithering, negative, progress bar, orientation). The GUI shows an exact live preview of the style.

**Architecture:**
- Rendering: the M2 Typst renderer grows from `RenderSettings` into `PageStyle` and also reports image boxes per page.
- Quantization: text pixels map to the nearest gray level (crisp); image boxes are dithered with Floyd–Steinberg at the chosen strength.
- Encoding: `xtc/codec.py` packs XTG/XTH pages, and `xtc/container.py` writes the XTC/XTCH container, following CrossPoint's reader (`lib/Xtc/Xtc/XtcTypes.h`, `XtcParser.cpp`), which CrossInk and Papyrix share.
- Preview: the GUI preview of XTC uses the very same quantize path, so it is pixel-identical to the file.

**Tech Stack:** M2 stack; dev `fonttools` only if a bundled family needs static instancing.

**Spec:** `docs/superpowers/specs/2026-11-16-epub-converter-optimizer-design.md` §8.9, §8.18, §9 items 9, 14, 15. Prerequisite: M2 merged.

## Global Constraints

- Everything in M1's and M2's Global Constraints still applies.
- **Format (verified against CrossPoint source):**
  - Little-endian throughout.
  - Container header 56 bytes, magic `b"XTC\0"` (1-bit) or `b"XTCH"` (2-bit); bytes 4–5 = `01 00` (version 1.0).
  - Page header 22 bytes, magic `b"XTG\0"` / `b"XTH\0"`.
  - XTG: row-major, MSB = leftmost pixel, bit 1 = white.
  - XTH: two bit planes, first plane = high bit, second = low bit. Each plane is column-major with columns from right to left, `ceil(h/8)` bytes per column, MSB = topmost pixel. Values: 0 white, 1 dark gray, 2 light gray, 3 black.
  - Chapter entries are 96 bytes. Start and end pages are stored **1-based**; CrossPoint subtracts 1, and the gist's "0-based" claim is wrong.
  - Title at metadata +0 (≤ 127 bytes), author at +128 (≤ 63 bytes); CrossPoint reads only these two metadata fields.
- Gray mapping constant `XTH_VALUES = {255: 0, 170: 2, 85: 1, 0: 3}` lives in one place and is marked "verify with devcheck on device".
- Bundled fonts: OFL only, static instances, ≤ 6 MB total in `src/eco/fonts/`, each family with its `OFL.txt` and a `SOURCES.md` entry (URL and version).
- Uploaded fonts: `.ttf`/`.otf` only, stored in `<job>/fonts/`, deleted with the job.
- Chapters start on a new page, so chapter-only renders equal full renders (live preview exactness).
- Default `PageStyle` values are exactly those in spec §8.18.

## Review Focus

1. Chapter titles longer than 79 bytes, or containing multi-byte UTF-8 (`Ü`, `—`) → truncated at a character boundary, still NUL-terminated, and CrossPoint-readable (Task 5 test).
2. A book that renders to zero pages (empty Markdown) → error `Nothing to render` and no XTC file written (Task 6 test).
3. An uploaded "font" that is not a font (renamed `.txt`) → HTTP 400 `Not a usable font file` (Task 7 test).
4. Orientation 90 on X3 → stored pages stay 528×792 (device-native) with the content rotated (Task 2 test).
5. Style JSON with an unknown key or an out-of-range value (`font_size: 500`) → `ValueError` naming the field, and HTTP 422 in the API (Task 1 and Task 7 tests).

### Task 3: Quantization

**Files:**
- Create: `src/eco/xtc/__init__.py`, `src/eco/xtc/quantize.py`, `tests/xtc/test_quantize.py`

**Interfaces:**
- Produces: `quantize_page(png: bytes, boxes: list[tuple[int, int, int, int]], style: PageStyle) -> Image.Image`. Returns an `L` image whose pixels are only {0, 85, 170, 255} (`xth`) or {0, 255} (`xtg`).
- Rules:
  - Outside boxes: nearest level, no dithering. XTH thresholds: `>212→255`, `>127→170`, `>42→85`, else `0`. XTG: `>=128→255`, else `0`.
  - Inside boxes, when `style.dither`: Floyd–Steinberg with the diffused error multiplied by `dither_strength/100`; otherwise nearest level.
  - `negative`: `255 - v` at the end.

```python
def _fs(region: np.ndarray, levels: np.ndarray, strength: float) -> np.ndarray:
    a = region.astype(np.float32); h, w = a.shape
    for y in range(h):
        for x in range(w):
            old = a[y, x]; new = levels[np.abs(levels - old).argmin()]; a[y, x] = new
            e = (old - new) * strength
            if x + 1 < w: a[y, x + 1] += e * 7 / 16
            if y + 1 < h:
                if x > 0: a[y + 1, x - 1] += e * 3 / 16
                a[y + 1, x] += e * 5 / 16
                if x + 1 < w: a[y + 1, x + 1] += e * 1 / 16
    return a.clip(0, 255).astype(np.uint8)
# ponytail: pure-Python loop over image boxes only; move to a C/numba kernel if image-heavy books get slow.
```

  - `negative=True` maps 255 to 0;

### Task 4: XTG/XTH page codec

**Files:**
- Create: `src/eco/xtc/codec.py`, `tests/xtc/test_codec.py`

**Interfaces:**
- Produces:
  - `XTH_VALUES = {255: 0, 170: 2, 85: 1, 0: 3}`
  - `encode_xtg(img: Image.Image) -> bytes`
  - `encode_xth(img: Image.Image) -> bytes`
  - `decode_page(data: bytes) -> Image.Image`
- Header: `struct.pack("<4sHHBBI8s", magic, w, h, 0, 0, data_size, bytes(8))`.
  - XTG: `data_size = ceil(w/8) * h`.
  - XTH: `data_size = w * ceil(h/8) * 2`.

```python
def test_xtg_header_and_bits():
    img = Image.new("L", (10, 2), 255); img.putpixel((0, 0), 0)
    d = encode_xtg(img)
    assert d[:4] == b"XTG\0" and struct.unpack("<HHBBI", d[4:14]) == (10, 2, 0, 0, 4)
    assert d[22] == 0x7F  # first pixel black (bit 0), rest of the byte white

def test_xth_known_vector():
    img = Image.new("L", (8, 8), 255); img.putpixel((7, 0), 0)  # top-right pixel black (value 3)
    d = encode_xth(img)
    plane = 8 * 1  # w * ceil(h/8)
    assert d[22] == 0x80 and d[22 + plane] == 0x80 and not any(d[23:22 + plane]) and not any(d[23 + plane:])

    assert list(decode_page(encode_xth(img)).getdata()) == list(img.getdata())
```

### Task 5: XTC/XTCH container

**Files:**
- Create: `src/eco/xtc/container.py`, `tests/xtc/test_container.py`

**Interfaces:**
- Produces:
  - `@dataclass(frozen=True) class Chapter: title: str; start: int; end: int` (0-based in the API)
  - `write_container(pages: list[bytes], *, hq: bool, width: int, height: int, title: str, author: str, language: str, chapters: list[Chapter], created: int | None = None) -> bytes`
  - `read_container(data: bytes) -> tuple[dict, list[bytes], list[Chapter]]`
- Layout:
  - **Header (56 bytes):**
    - magic (4)
    - `01 00`
    - u16 pageCount
    - u8 readDirection 0, u8 hasMetadata 1, u8 hasThumbnails 0, u8 hasChapters
    - u32 currentPage 1
    - u64 metadataOffset 56, u64 indexOffset, u64 dataOffset, u64 thumbOffset 0, u64 chapterOffset 312
  - **Metadata at 56 (256 bytes):**

    | Offset | Field |
    |---|---|
    | +0 | title (UTF-8, ≤ 127 bytes, cut at a character boundary, NUL-padded) |
    | +128 | author (≤ 63 bytes) |
    | +192 | `"eco"` (≤ 31 bytes) |
    | +224 | language (≤ 15 bytes) |
    | +240 | u32 created |
    | +244 | u16 `0xFFFF` |
    | +246 | u16 chapterCount |
    | rest | zero |

  - **Chapters at 312, 96 bytes each:** name (≤ 79 bytes + NUL in 80 bytes), u16 start+1 at +80, u16 end+1 at +82, zeros.
  - **Index:** per page `struct.pack("<QIHH", offset, size, width, height)`.
  - **Data:** pages back to back.

  - The first chapter, starting at page 0, stores `1` at offset 312+80.
  - A 200-character title of `"Ü"` is stored as ≤ 127 bytes that decode as UTF-8 and end with NUL.
  - `read_container(write_container(...))` returns the same pages and chapters.
